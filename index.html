API, HTTP, AJAX & Async JavaScript

Frontend Development Notes

1. What is an API?

API stands for Application Programming Interface.

An API is an interface that allows different software systems to communicate with each other.

Example

Website / Mobile App
        ↓
       API
        ↓
Server / Database

Examples of APIs

  • YouTube API
  • Google Maps APIs
  • GitHub API

An API does not have to be a Web API. APIs can also exist inside operating systems, libraries, frameworks, and applications.

2. Web APIs

A Web API allows applications to communicate over a network, commonly using HTTP.

Typical Communication

Client
  ↓
HTTP Request
  ↓
API / Server
  ↓
Process Request
  ↓
HTTP Response
  ↓
Client

Common Data Formats

  • JSON
  • XML

JSON Example

{
    "id": 1,
    "name": "Mohamed"
}

JSON is very common in modern Web APIs.

REST is an architectural style, not a data format. REST APIs can return JSON, XML, or other formats.

3. What is HTTP?

HTTP stands for HyperText Transfer Protocol.

HTTP is an application-layer protocol used for communication between clients and servers on the Web.

HTTP can transfer:

  • HTML
  • CSS
  • JavaScript
  • Images
  • JSON
  • Videos
  • Other resources

Basic Communication

Request → Response

4. HTTP Request & Response

  1. Client sends an HTTP Request.
  2. Server receives the Request.
  3. Server processes the Request.
  4. Server sends an HTTP Response.
  5. Client receives the Response.

Example

Browser
   ↓
GET /users
   ↓
Server
   ↓
JSON Response
   ↓
Browser

5. TCP, IP & HTTP

IP — Internet Protocol

IP is responsible mainly for addressing and routing data between devices.

TCP — Transmission Control Protocol

TCP provides reliable and ordered delivery of data.

HTTP

HTTP defines how web requests and responses are structured and what they mean. 

IP   → Where should the data go?
TCP  → How can data be delivered reliably?
HTTP → What is the request/response?

HTTP/1.1 and HTTP/2 commonly use TCP, while HTTP/3 uses QUIC over UDP.

8. HTTP vs HTTPS

HTTP

HyperText Transfer Protocol.

HTTPS

HTTPS is HTTP transported over a secure TLS connection. 

HTTPS = HTTP + TLS

TLS provides:

  • Encryption
  • Data integrity
  • Server authentication

HTTPS helps protect sensitive information such as passwords, credit card information, and authentication tokens.

9. Types of APIs

Web APIs

APIs that communicate over a network.

  • REST API
  • GraphQL API

Local APIs

APIs used inside an operating system, platform, or application.

  • Windows API
  • Android APIs
  • Browser Web APIs

REST is an architectural style.

GraphQL is a query language and runtime for APIs.

10. AJAX

AJAX stands for Asynchronous JavaScript and XML.

AJAX is a technique for making asynchronous network requests and updating parts of a webpage without requiring a full page reload or navigation.

Despite the name, AJAX does not require XML.

AJAX can work with:

  • JavaScript
  • HTTP
  • XMLHttpRequest
  • Fetch API
  • JSON
  • HTML / CSS

Traditional Approach

Click
 ↓
Reload entire page
 ↓
Display new data

AJAX-style Approach

Click
 ↓
Send request in background
 ↓
Receive data
 ↓
Update part of the page

11. Synchronous vs Asynchronous

Synchronous

Tasks are executed sequentially. The next operation waits for the current one. 

Task 1
  ↓
Task 2
  ↓
Task 3

Asynchronous

An operation can start without blocking the rest of the program while waiting for its result. 

Start Task
    ↓
Continue other work
    ↓
Task finishes later

Common Examples

  • Network requests
  • Timers
  • File operations

12. Callback

A callback is a function passed to another function to be executed later. 

doSomething(function () {
    console.log("Finished");
});

When many asynchronous operations depend on each other, callbacks can become deeply nested.

This is commonly called Callback Hell or Pyramid of Doom.

13. Promise

A Promise is a JavaScript object that represents the eventual completion or failure of an asynchronous operation.

Promise States

  1. Pending — Operation hasn't finished yet.
  2. Fulfilled — Operation completed successfully.
  3. Rejected — Operation failed.

14. Promise Methods

then()

Runs when the Promise is fulfilled. 

promise.then(result => {
    console.log(result);
});

catch()

Handles a rejected Promise. 

promise.catch(error => {
    console.log(error);
});

finally()

Runs when the Promise is settled, whether fulfilled or rejected. 

promise.finally(() => {
    console.log("Finished");
});

15. Promise Chaining

.then() returns a new Promise. This allows us to chain multiple asynchronous operations. 

doSomething()
    .then(result => {
        return doSomethingElse(result);
    })
    .then(result => {
        return doThirdThing(result);
    })
    .catch(error => {
        console.log(error);
    });

The returned value from one .then() can be passed to the next one.

16. Fetch API

The Fetch API is a modern JavaScript API for making network requests.

Fetch is Promise-based. 

fetch(url)
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.log(error);
    });

17. Fetch & HTTP Errors

Important: fetch() does not automatically reject its Promise for HTTP errors such as 404 or 500.

If the server responds, fetch normally fulfills with a Response object.

Check response.ok

fetch(url)
    .then(response => {

        if (!response.ok) {
            throw new Error(
                `HTTP Error: ${response.status}`
            );
        }

        return response.json();
    });

18. Sending Data with Fetch

By default, fetch() uses the GET method. 

fetch(url);

POST Example

fetch(url, {
    method: "POST",

    headers: {
        "Content-Type": "application/json"
    },

    body: JSON.stringify({
        name: "Mohamed"
    })
});

A GET request made through Fetch cannot have a request body.

19. async / await

async / await is modern JavaScript syntax for working with Promises.

It does not replace Promises. It provides a cleaner syntax for working with them.

async

An async function always returns a Promise. 

async function getData() {
    return "Hello";
}

await

await waits for a Promise to settle and gives the fulfilled value. 

async function getData() {

    const response = await fetch(url);

}

20. async / await Example

Promise Style

fetch(url)
    .then(response => response.json())
    .then(data => console.log(data))
    .catch(error => console.log(error));

async / await Style

async function getData() {

    const response = await fetch(url);

    const data = await response.json();

    console.log(data);
}

async / await often makes complex asynchronous code easier to read.

21. Important await Point

await pauses the execution of the current async function until the Promise settles.

It does not freeze the entire browser or JavaScript application. 

async function example() {

    const data = await getData();

    console.log(data);
}

22. try / catch

try...catch is used to handle runtime exceptions.

try

Contains code that might throw an error.

catch

Runs when an error is thrown.

finally

Runs whether an error occurred or not. 

try {

    // Code that might throw

} catch (error) {

    // Handle error

} finally {

    // Always runs

}

23. try / catch + Fetch

A common pattern when working with APIs: 

async function getUsers() {

    try {

        const response = await fetch(url);

        if (!response.ok) {
            throw new Error(
                `HTTP Error: ${response.status}`
            );
        }

        const users = await response.json();

        console.log(users);

    } catch (error) {

        console.log(error);

    } finally {

        console.log("Request finished");

    }
}

Flow

 ↓
Request
 ↓
Success → Continue
 ↓
Error → catch
 ↓
finally
